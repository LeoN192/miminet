# Правила работы команды

Краткий устав командной работы над репозиторием miminet. Технический контекст
для агентов — `AGENTS.md`, архитектура — `docs/ARCHITECTURE.md`, задачи — в
GitHub issues.

## Ветки

Формат названия: `<роль>/<issue>-<slug>`, где роль — ник участника, например:

    leonid/534-quiz-grading

Работа всегда ведётся в своей ветке; `main` — защищённая ветка (см. ниже).

## В main — только через PR

Прямые коммиты и пуши в `main` запрещены. Каждое изменение проходит PR с
шаблоном описания: ссылка на issue, что изменено, чем проверено, отметки про
секреты и handoff.

## Секреты

Запрещено читать и коммитить:

- `vk_auth.json`
- `miminet_secret.conf`
- `client_yandex.json`
- `front/.env`, `back/.env` (файлы `*.env.example`, если появятся, — разрешены)

Для агентов OpenCode это уже зашито в `opencode.json`: чтение и правка этих
файлов блокируются deny-правилами, а любая shell-команда требует
подтверждения человека. Утечка секрета считается инцидентом: секрет
заменяют, а не «удаляют из истории».

## Handoff

Сессия без записанного handoff не считается завершённой. В конце работы:

1. заполни шаблон `.team/templates/handoff.md` — готовый текст кладётся в PR
   (в описание или комментарий);
2. добавь одну строку в `.team/session-log.md`.
